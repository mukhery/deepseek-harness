# Agent Note: Drop the bilingual documentation policy

Status: implemented

## Problem

Every repository document — READMEs, `docs/`, package docs, and Agent Notes — kept a paired `.zh.md` translation plus an `.i18n.yaml` consistency sidecar, enforced by a dedicated pairing gate, a merge driver, an automated translation-pairing pipeline, and a calibrated translation prompt (`docs/i18n/`, the `dsh-translate-docs` skill, and roughly two dozen `scripts/translation-*`/`*-pairing*` files). The documentation website mirrored the split as two VitePress locales (`root` = Chinese, `en` = English under `/en/`). Maintaining this apparatus — regenerating translations, keeping the pairing gate, merge driver, and lefthook hook green, and keeping the website's locale-aware routing correct — cost more in ongoing tooling surface than the project could justify continuing to carry, and the owning team decided to stop maintaining a second language for repository documentation and the website. The product's own end-user UI language switcher (`packages/client/locale`) is a separate, independently-motivated feature and is unaffected.

## Decision

The repository is English-only for documentation and the website going forward. Every `.zh.md` and `.i18n.yaml` file was deleted, along with `docs/i18n/`, the `dsh-translate-docs` skill, and every script whose sole purpose was translation pairing (`translation-pairing*.ts`, `translation-prompt*.ts`, `verify-translation-*.ts`, `gen-translation-brief.ts`, `merge-translation-pairing.ts`, `paired-markdown-derivatives.ts`, and their fixtures/snapshots). `lefthook.yml` and `scripts/run-gates.ts` no longer run a pairing gate; `scripts/install-lefthook.mjs` no longer installs the pairing merge driver. Gates that used to skip or dedupe `.zh.md` content (`verify-md-links`, `verify-md-wrap`, `verify-mermaid`, `verify-type-equiv`, `doc-typecheck`) had that logic removed rather than left dead. `scripts/gen-cordis-catalog.ts` writes each generated subsystem page once instead of into both language sides and no longer re-records a pairing sidecar.

The documentation website (`website/docs.ts`, `website/.vitepress/config.ts`, `scripts/project-doc-site.ts`) dropped its locale dimension entirely: one route tree, English content, no `/en/` prefix, no locale switcher in the navigation bar. `DocsPage` no longer carries `locale`/`contentLocale` fields, and `DocsSidebar` collapsed from six locale-qualified collections (`zh-guide`, `en-guide`, …) to three (`guide`, `develop`, `reference`).

**The frozen `.agents/notes/archived/` tree is exempt and untouched.** Every already-sealed archived Agent Note keeps its `.zh.md` and `.i18n.yaml` exactly as sealed — per this repository's own archive policy, a sealed artifact is never edited, translated, reformatted, or deleted, regardless of what prompted the archival. `scripts/archived-agent-notes.ts` now accepts two shapes: a legacy triplet (`.md` + `.zh.md` + `.i18n.yaml`), validated exactly as before, for anything archived before this change; and a standalone `.md`, for anything archived after it. The five active Agent Notes whose entire subject was the now-removed tooling (bilingual pairing gate, translation prompt v4, briefed/lightweight/automatic translation-pairing updates) were archived as standalone English files under this same PR, since their rationale no longer guides any current decision except as a record of why the machinery existed and was retired.

Every other active Agent Note that referenced the removed tooling (dangling links into `docs/i18n/`, `dsh-translate-docs`, or a deleted script; claims like "the English and Chinese README sides share the same technical structure" or "a paired `.zh.md` block reuses the unsuffixed sibling's manifest entry") was updated to drop the now-false claim, consistent with the standing rule that an implemented note stays current with what shipped. Notes that only narrate a past, dated attempt or decision (an Alternatives-considered entry, a Problem/Decision section describing what was true and fixed at the time) were left as historical record rather than rewritten, since they no longer make any operationally false claim about current behavior.

## Alternatives considered

**Keep the tooling and just stop authoring new translations.** Rejected: the pairing gate, merge driver, and lefthook hook would keep firing on every commit for zero ongoing benefit, and the corpus would silently drift out of sync with no mechanism catching it — worse than removing the apparatus outright.

**Delete only the `.zh.md`/`.i18n.yaml` files and leave the scripts/gates in place, erroring loud when they find nothing to check.** Rejected: dead gates that always pass on an empty input are exactly the kind of never-fires check this repository's own conventions warn against; the scripts existed to serve a corpus that no longer exists, so they are dead code, not dormant capability.

**Also strip the sealed `.zh.md`/`.i18n.yaml` files out of `.agents/notes/archived/`.** Rejected: the archive's entire value is that a sealed snapshot never changes for any reason, including a change to the policy that produced it; rewriting 142 already-sealed notes to match a new policy is precisely the kind of retroactive edit the archive exists to forbid, and doing so would also require rewriting every git blob hash the append-only manifest already sealed.

**Keep `packages/client/locale` in scope too.** Rejected: it is a distinct, independently motivated product feature (the running application's own UI language, chosen by an end user), not repository documentation policy; conflating the two would have deleted a shipped capability nobody asked to remove.

## Consequences

`pnpm run doc-sync`, `pnpm run build`, and the documentation website build all run without the removed scripts; `docs:build` renders 1163 resolving internal fragment references against the new single-locale site. The archive verifier now checks 431 frozen artifacts (426 pre-existing plus the 5 newly archived) across a mixed triplet/standalone-file archive, and reports the same "N frozen artifact(s) checked" success it always has. New Agent Notes, and any future archival, use plain English `.md` files with no sidecar. A contributor who wants Chinese documentation again would need to reintroduce the pairing gate, the merge driver, and the website's locale split from scratch — this decision does not preserve a partial mechanism to build back onto.
